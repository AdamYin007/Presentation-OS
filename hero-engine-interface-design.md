# Hero Engine Interface Design

## Role
AWE Presentation OS — Hero Engine Interface Specification

## Task
Define a minimal, backward-compatible interface that transforms Story + Hero Sequence into Slide Render Metadata consumed by ppt-factory.

## Design Summary

### Core Principle

Hero Engine is a **transformation layer**, not a replacement. It reads existing story JSON and optional hero sequence JSON, merges them, and produces a single enriched object that ppt-factory consumes exactly as before.

```
Story JSON (existing) ──┐
                        ├──► Hero Engine ──► Enriched Story ──► ppt-factory (unchanged)
Hero Sequence JSON ──────┘
```

The enriched story is a superset of the existing story JSON. Every existing field is preserved verbatim. Hero metadata is added as an optional `hero` object on each slide.

---

### 1. Data Model

#### 1.1 Enriched Story (top-level)

The output of Hero Engine. It is a valid story JSON with one new top-level key:

```jsonc
{
  // ── Preserved verbatim from story JSON ──
  "name": "digital-pathology-15",
  "title": "...",
  "audience": "...",
  "style": "medical-consulting",
  "slides": [ /* array of enriched slide objects, see 1.2 */ ],

  // ── New (optional, injected by Hero Engine) ──
  "_meta": {
    "hero_engine_version": "1.0.0",
    "hero_sequence_source": "digital-pathology-15-hero-sequence.json",
    "generated_at": "2026-06-30T12:00:00Z",
    "narrative_arc": "开场(1-5) → 方案(6-8) → 信任(9-11) → 行动(12-15)"
  }
}
```

The `_meta` key is prefixed with underscore to signal it is engine metadata, not story content. ppt-factory ignores unknown keys.

#### 1.2 Enriched Slide Object

Each slide in the `slides` array gets an optional `hero` field merged from the hero sequence:

```jsonc
{
  // ── Preserved verbatim from story JSON ──
  "no": 1,
  "type": "cover",
  "pattern": "Hero Statement",
  "title": "...",
  "message": "...",

  // ── New (optional, injected by Hero Engine) ──
  "hero": {
    "pattern_id": "H-001",
    "statement": "数字病理的本质，是 AI 和软件驱动的能力升级",
    "visual_focus": "超大品牌标语 + 极简背景（数字病理切片抽象图）",
    "decision_goal": "建立品牌认知，传递核心定位",
    "first_impression_5s": "这是一次关于数字病理的战略汇报，91360 是主角",
    "layout_hint": "居中排版，留白 >= 60%，品牌色主视觉",
    "estimated_reveal_time_s": 3
  }
}
```

When no hero sequence is provided, the `hero` field is absent. ppt-factory treats it as `undefined` and renders identically to today.

#### 1.3 Hero Sequence Input (reference)

The hero sequence JSON is the input to Hero Engine. Its structure is preserved as-is; Hero Engine reads it and merges into the story:

```jsonc
{
  "meta": {
    "story_id": "digital-pathology-15",
    "hero_layer_version": "1.0.0",
    "narrative_arc": "..."
  },
  "slides": [
    {
      "slide_no": 1,
      "hero_pattern_id": "H-001",
      "hero_statement": "...",
      "visual_focus": "...",
      "decision_goal": "...",
      "first_impression_5s": "...",
      // optional
      "estimated_reveal_time_s": 3
    }
  ],
  "narrative_flow": { /* acts */ },
  "transition_logic": [ /* inter-slide connections */ ]
}
```

Hero Engine extracts only the `slides` array and merges by matching `slide_no` to `story.slides[].no`.

### 2. Required Fields

Hero Engine maps hero sequence fields to enriched slide fields. All mappings are **one-to-one**:

| Hero Sequence Field | Enriched Slide Field | Type | Notes |
|---|---|---|---|
| `slide_no` (key) | — | — | Join key, not stored in output |
| `hero_pattern_id` | `hero.pattern_id` | string | Pattern ID from hero-library.json |
| `hero_statement` | `hero.statement` | string | Overrides story `title` if present |
| `visual_focus` | `hero.visual_focus` | string | Renderer hint |
| `decision_goal` | `hero.decision_goal` | string | For audience targeting |
| `first_impression_5s` | `hero.first_impression_5s` | string | For QA/validation |

---

### 3. Optional Fields

| Field | Type | Source | Purpose |
|---|---|---|---|
| `hero.layout_hint` | string | Derived from `hero_pattern_id` → lookup in hero-library.json | Renderer layout guidance |
| `hero.estimated_reveal_time_s` | number | From hero sequence | Timing control for presenter mode |
| `hero.audience_override` | string | From hero sequence (future) | Override story-level audience per slide |
| `hero.media` | object | Future | Image/video references for hero visual |
| `_meta` (top-level) | object | Generated by Hero Engine | Traceability |

The `layout_hint` is auto-derived: given `hero_pattern_id: "H-001"`, Hero Engine looks up `hero-library.json` patterns array, finds the pattern with matching `id`, and copies its `recommended_layout` field into `hero.layout_hint`.

---

### 4. How Renderer Consumes Hero Metadata

The renderer (ppt-factory run.js) accesses hero metadata via `slide.hero`. The consumption contract is:

#### 4.1 Contract

```
IF slide.hero EXISTS:
    Use slide.hero.statement as the page's primary headline (instead of slide.title)
    Use slide.hero.visual_focus as rendering hint (renderer may ignore if layout is fixed)
    Use slide.hero.layout_hint for layout selection (future)
    Use slide.hero.decision_goal for audience-targeted content filtering (future)

ELSE (current behavior):
    Use slide.title as headline
    Use slide.message as subtitle
    Render according to slide.type pattern (unchanged)
```

#### 4.2 Concrete Example: Cover Slide

**Current (no hero):**
```js
// run.js cover() function
slide.addText(s.title, { fontSize: 32, bold: true, color: comp.C.navy });
slide.addText(s.message, { fontSize: 15, color: comp.C.gray });
```

**With hero (no code change needed):**
```js
// Same code, but s.title is already overridden by Hero Engine:
// Hero Engine sets: s.title = s.hero.statement
// So the existing code renders the hero statement automatically.
```

Key insight: **Hero Engine mutates `slide.title` to equal `slide.hero.statement`** before passing to the renderer. The renderer code stays identical. The hero metadata (`visual_focus`, `decision_goal`, `layout_hint`) is available on `slide.hero` for future renderer upgrades but does not break existing rendering.

#### 4.3 Consumer Access Points

| Consumer | Access | Usage |
|---|---|---|
| Cover renderer | `s.title` | Already set to hero.statement by Hero Engine |
| Footer | `s.hero.pattern_id` | Could show pattern badge (future) |
| Presenter mode | `s.hero.estimated_reveal_time_s` | Timer display (future) |
| Audience selector | `s.hero.decision_goal` | Show/hide content per audience (future) |
| QA tool | `s.hero.first_impression_5s` | Validate 5-second readability (future) |

### 5. Backward Compatibility Strategy

#### 5.1 Schema Level

- **Story JSON**: Hero Engine never modifies existing fields. It only adds `hero.*` and mutates `title` (which the renderer already reads).
- **Hero Sequence JSON**: Standalone file, never merged into story JSON directly. It is read-only input.
- **Enriched Story**: Is-a superset of story JSON. Any consumer that reads `slide.no`, `slide.type`, `slide.title`, `slide.message` works identically.

#### 5.2 Runtime Level

Three operating modes:

| Mode | Hero Sequence | Behavior |
|---|---|---|
| **Full** | Present | Hero Engine runs. Mutates `title`, adds `hero.*`, adds `_meta` |
| **Story-only** | Absent | Hero Engine skips. Output is identical to existing story JSON. ppt-factory renders unchanged |
| **Partial** | Present but no match for some slides | Hero Engine merges what it can. Unmatched slides get no `hero` field. Mixed behavior |

Mode selection is controlled by a single CLI flag:

```bash
# Full mode (default when hero-sequence file exists)
awe-dev run factory ppt-factory --story digital-pathology-15

# Story-only mode (explicitly skip hero layer)
awe-dev run factory ppt-factory --story digital-pathology-15 --no-hero

# Custom hero sequence path
awe-dev run factory ppt-factory --story digital-pathology-15 --hero-sequence path/to/custom.json
```

#### 5.3 Pattern Library Level

Hero Engine reads `hero-library.json` at runtime. If the file is missing or malformed:
- Log a warning
- Continue without layout hints
- Do NOT fail the build

### 6. Migration Path

#### Phase 0: Current State (no changes)

```
Story JSON ──► ppt-factory ──► PPTX
```

#### Phase 1: Hero Engine as Optional Middleware (zero risk)

```
Story JSON ──┬──► Hero Engine (optional) ──► Enriched Story ──► ppt-factory ──► PPTX
             └───────────────────────────────► (passthrough) ──────────────────────────┘
```

- Hero Engine is a separate module: `registry/packages/ppt-factory/src/hero-engine.js`
- Default: passthrough mode (no hero sequence file = no transformation)
- When hero sequence file exists: enrichment runs
- ppt-factory run.js unchanged

#### Phase 2: Title Override Active

- Hero Engine begins mutating `slide.title = slide.hero.statement`
- Existing slide renderers automatically render the hero statement
- Visual improvement with zero code changes to renderers

#### Phase 3: Renderer Awareness (incremental)

- Individual slide renderers (`cover()`, `executive()`, etc.) begin reading `slide.hero.*` for enhanced rendering
- Each renderer upgrade is a separate PR, independently testable
- Fallback: if `slide.hero` is absent, renderer uses existing logic

Example upgrade for cover renderer:

```js
// Before (Phase 0):
slide.addText(s.title, { fontSize: 32, bold: true, color: comp.C.navy });

// After (Phase 3):
const heroText = s.hero?.statement || s.title;
slide.addText(heroText, { fontSize: 32, bold: true, color: comp.C.navy });
// Optionally: use s.hero?.visual_focus to select background image
```

#### Phase 4: Audience-Specific Decks

- Hero Engine gains `audience_filter` mode
- Given `--audience 院长`, it filters slides where `hero.decision_goal` targets non-院长 audiences
- Produces audience-tailored PPTX from the same story + hero sequence

### 7. Data Flow Diagram

```
┌─────────────────────────────────────────────────────────────┐
│                    Hero Engine (src/hero-engine.js)          │
│                                                              │
│  Input:                                                      │
│    story     = Story JSON (existing, immutable)              │
│    sequence  = Hero Sequence JSON (optional)                 │
│    library   = hero-library.json (optional, for layout hints)│
│                                                              │
│  Process:                                                    │
│    1. Match sequence.slides[N].slide_no ↔ story.slides[N].no│
│    2. For each match:                                        │
│       a. story.slides[N].title = sequence.hero_statement     │
│       b. story.slides[N].hero = {                           │
│            pattern_id, statement, visual_focus,              │
│            decision_goal, first_impression_5s,               │
│            layout_hint (from library),                         │
│            estimated_reveal_time_s                            │
│          }                                                   │
│    3. Attach _meta to story                                  │
│                                                              │
│  Output:                                                     │
│    Enriched Story JSON (superset of input story)             │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   ppt-factory (bin/run.js)                   │
│                                                              │
│  Receives: Enriched Story JSON                               │
│  Reads: slide.title (may be hero.statement)                  │
│  Reads: slide.hero.* (optional, for future enhancements)     │
│  Renders: Identical output for stories without hero field    │
└─────────────────────────────────────────────────────────────┘
```

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Hero statement longer than 15 chars breaks cover layout | Medium | Hero Engine validates length; warns but does not block |
| Mismatch between `slide_no` and `no` causes silent skip | Low | Hero Engine logs unmatched sequences |
| Title mutation affects footer/page-number generation | Low | Hero Engine preserves original title in `hero.original_title` |
| Hero sequence file missing at runtime causes confusion | Medium | Clear error message: "No hero sequence found. Rendering in story-only mode." |
| Future renderer upgrades introduce visual regressions | Medium | Each renderer upgrade tested against baseline PPTX diff |

---

## Estimated Impact

| Dimension | Impact |
|---|---|
| Story JSON compatibility | 100% backward compatible. Hero Engine output is a valid story JSON. |
| ppt-factory code changes | Phase 1: zero changes. Phase 2: title mutation only. Phase 3+: incremental per-renderer. |
| CLI usage | Unchanged. New flags are additive (`--no-hero`, `--hero-sequence`). |
| PPTX output (no hero) | Bit-identical to current output. |
| PPTX output (with hero) | Title text changes; layout identical until Phase 3. |
| Development effort | Phase 1: ~2 days. Phase 2: ~0.5 days. Phase 3+: ~1 day per renderer. |

## Next Suggestion

Implement Phase 1 as a standalone `hero-engine.js` module in `registry/packages/ppt-factory/src/`. It should:
1. Accept story JSON and optional hero sequence JSON
2. Perform the merge described in Section 4
3. Return enriched story JSON
4. Be callable from run.js as: `const enriched = require('../src/hero-engine')(story, heroSequence)`

This is a pure function with no side effects, fully testable in isolation, and introduces zero risk to existing rendering.
