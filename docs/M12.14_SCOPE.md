# M12.14 — Generation Quality Traceability & Verifiable QA Report

## Overview

M12.14 introduces a **unified quality traceability layer** for the markdown-to-PPTX pipeline. It does not add new slide types, renderers, or visual elements. Instead, it makes the **quality of every generated presentation interpretable, auditable, and regress-resistant**.

The core problem: M12.8 produces two separate QA checkers (content + visual) that each generate their own reports in different locations with different formats. There is no single source of truth for "is this deck good enough?" and no structured checkpoint that can be compared across runs to detect regressions.

M12.14 solves this by:
1. Standardizing a **machine-readable quality manifest** emitted alongside every PPTX
2. Consolidating all QA checks into a **single entry point** (`check-m12-14-quality-traceability.cjs`)
3. Producing a **human-readable QA summary** suitable for user consumption
4. Enabling **diff-based regression detection** via deterministic checkpoint comparison

### Current QA Gaps

1. **Fragmented reports**: M12.8 content QA writes to `examples/business-review/qa-report.{json,md}`; M12.8 visual QA writes to `/tmp/...`. No single query surface.
2. **No machine-readable manifest at the PPTX level**: Users cannot inspect a `.pptx` and know what checks passed without running a checker separately.
3. **No regression baseline**: Each run produces fresh numbers; there is no way to diff "today's quality" vs "yesterday's quality."
4. **No user-facing summary**: The `qa-report.md` is developer-oriented (pass/fail counts, raw issue lists). A presentation recipient should see a one-page quality digest.
5. **Pipeline output has no embedded quality metadata**: `runPipeline()` returns `{ slideSpecs, layoutPlan, pptxBuffer, ... }` but no quality score or checklist result.

## M12.14 Objectives

### Primary Objective

Establish a **deterministic, reproducible quality traceability system** that:
- Emits a single `quality-manifest.json` alongside every generated PPTX
- Runs all relevant QA checks through one consolidated entry point
- Produces a human-readable `QA-SUMMARY.md` suitable for sharing with stakeholders
- Enables `npm run check:m12-14-regression` to diff manifests and flag regressions

### Secondary Objectives

- Provide a **quality score** (0–100) derived from weighted check results
- Make **failure reasons specific and actionable** (not just "Content QA failed")
- Support **checkpoint mode**: save current manifest, then compare future runs against it

## Scope In

### What M12.14 Will Deliver

#### 1. Quality Manifest Schema (`quality-manifest.json`)

A deterministic JSON file emitted alongside every PPTX output. Structure:

```json
{
  "version": "1.0.0",
  "generatedAt": "2026-07-XXTXX:XX:XX.XXXZ",
  "input": "fixtures/document-ingest/sample-markdown.md",
  "pipeline": {
    "format": "markdown",
    "style": "minimal-modern",
    "title": "Sample Presentation"
  },
  "deck": {
    "slideCount": 10,
    "contentSlides": 7,
    "sectionDividers": 2,
    "closingSlide": true
  },
  "qualityScore": 85,
  "checks": [
    {
      "id": "title-completeness",
      "category": "content",
      "status": "pass",
      "detail": "All 10 slides have non-empty titles"
    },
    {
      "id": "source-ref-coverage",
      "category": "content",
      "status": "pass",
      "detail": "7/7 content slides have source references",
      "metrics": { "total": 7, "covered": 7, "coverage": 1.0 }
    },
    {
      "id": "duplicate-detection",
      "category": "content",
      "status": "warn",
      "detail": "1 pair of slides share similar body text (>80% overlap)",
      "metrics": { "pairsChecked": 45, "similarPairs": 1, "maxOverlap": 0.83 }
    },
    {
      "id": "layout-diversity",
      "category": "visual",
      "status": "pass",
      "detail": "6 distinct layouts used across 10 slides",
      "metrics": { "distinctLayouts": 6, "mostCommon": "two-column", "frequency": 0.3 }
    }
  ],
  "scoreBreakdown": {
    "content": { "weight": 0.4, "raw": 90, "weighted": 36 },
    "visual": { "weight": 0.3, "raw": 80, "weighted": 24 },
    "structure": { "weight": 0.2, "raw": 95, "weighted": 19 },
    "completeness": { "weight": 0.1, "raw": 70, "weighted": 7 }
  }
}
```

#### 2. Consolidated Checker (`scripts/check-m12-14-quality-traceability.cjs`)

A single entry point that:
- Runs content QA checks (title completeness, source refs, duplicates, notes quality, layout diversity, closing slide verification)
- Runs structural checks (section dividers, role distribution, slide count reasonableness)
- Optionally runs visual QA checks if LibreOffice is available (PPTX validity, PDF page count match, blank page detection)
- Emits `quality-manifest.json` to the output directory
- Emits `QA-SUMMARY.md` (one-page human digest)
- Exits with code 0 if no failures, 1 if any failures

#### 3. Human-Readable QA Summary (`QA-SUMMARY.md`)

A concise, stakeholder-friendly report:

```markdown
# Presentation Quality Summary

**Input**: q2-business-review.md  
**Generated**: 2026-07-XX  
**Quality Score**: 85/100 ✓

| Category | Score | Status |
|----------|-------|--------|
| Content   | 90/100 | ✓ All titles present, source refs complete |
| Visual    | 80/100 | ⚠ 1 sparse slide detected |
| Structure | 95/100 | ✓ Proper section dividers and closing slide |
| Completeness | 70/100 | ⚠ Speaker notes missing on 2 slides |

**Key Findings**:
- 1 slide pair has similar body text (consider rewording)
- 2 slides lack speaker notes

**Verdict**: PASS — ready for review
```

#### 4. Regression Detection (`npm run check:m12-14-regression`)

Compares current `quality-manifest.json` against a stored baseline. Reports:
- Score deltas per category
- New failures / resolved issues
- Changed metrics (e.g., "source ref coverage dropped from 100% to 85%")

#### 5. Pipeline Integration Hook

Optional: `runPipeline()` gains an `emitManifest: true` option that automatically produces the manifest file alongside the PPTX buffer. This is **non-breaking** — default behavior remains unchanged.

## Scope Out

### What M12.14 Will NOT Do

| Excluded | Reason |
|----------|--------|
| New slide types or visual elements | Out of scope for quality traceability |
| PPTX editing / revision engine | Covered by M12.9 |
| New chart/diagram types | Covered by M12.10 |
| Theme engine changes | Not relevant to quality measurement |
| CLI argument changes beyond existing flags | The checker uses its own invocation |
| Real-time quality feedback during generation | Future milestone; batch analysis is sufficient for M12.14 |
| Cloud-based quality services | Must remain offline, zero-dependency |
| UI / GUI components | Terminal-only delivery |

## Technical Risks

| Risk | Mitigation |
|------|-----------|
| Manifest schema changes break backward compatibility | Include `"version"` field; checker validates schema before writing |
| Visual QA requires LibreOffice (platform-dependent) | Visual checks are optional; degrade gracefully with warning |
| Performance impact on large decks (>50 slides) | Duplicate detection uses O(n²) comparison; cap at 50 slides with warning |
| Score formula subjectivity | Document the weight formula; make weights configurable via `package.json` or env vars |
| Adding to `runPipeline()` may affect existing callers | Use optional parameter with default `false`; no breaking change |

## Acceptance Criteria

### Must-Have (Blocking)

1. **Single entry point**: `node scripts/check-m12-14-quality-traceability.cjs` runs all content + structural checks and exits 0 on sample-markdown.md
2. **Manifest emitted**: `quality-manifest.json` is written to the output directory with valid schema (all required fields present)
3. **Quality score computed**: Score is a deterministic function of check results (same input → same score)
4. **Human-readable summary**: `QA-SUMMARY.md` is written with score, per-category breakdown, and key findings
5. **Regression detection works**: Running twice produces diffable manifests; `npm run check:m12-14-regression` reports deltas
6. **No breaking changes**: Existing checkers (M12.1–M12.12) still pass; existing `runPipeline()` calls unaffected

### Should-Have

7. **Visual QA integration**: If LibreOffice is available, PPTX validity and blank page checks are included
8. **Source ref tracking**: Manifest includes per-slide sourceRef presence and coverage percentage
9. **Duplicate detection**: Body text similarity reported with overlap percentage

### Nice-to-Have

10. **Pipeline hook**: `runPipeline(input, { emitManifest: true })` produces manifest automatically
11. **Configurable weights**: Score weights adjustable via environment variable or config file

## Non-Goals Reminder

This is **quality measurement**, not **quality improvement**. We do not fix bad content; we measure and report it. Fixing issues found by M12.14 checks is a future milestone's job.
