# Trademark & Patent Risk Disclosure Checklist

**Purpose**: Identify IP risks before public disclosure, marketing, or product launch.

## Trademark Risks

### Project Name & Branding

- [ ] Has the project name ("Presentation OS", "AWE") been searched in trademark databases?
- [ ] Are there conflicting trademarks in the same class (software/tools)?
- [ ] Is the logo/design registered or searchable for conflicts?
- [ ] Is the domain name secured?
- [ ] Are social media handles secured?

### Before Public Promotion

- [ ] Preserve first-use evidence (screenshots, release notes, commit dates)
- [ ] Document marketing materials with dates
- [ ] Record any third-party references that establish brand association

### Third-Party Trademarks

- [ ] Do NOT use third-party trademarks without permission
- [ ] Do NOT include competitor logos in comparisons without fair-use review
- [ ] Product names referencing other brands require legal review
- [ ] Open-source project names may be trademarked even if code is licensed

## Patent Risks

### What Copyright Does NOT Protect

- Abstract ideas, concepts, or functionality
- Technical principles or algorithms
- Methods of operation
- Data formats (in some jurisdictions)
- Business methods (varies by jurisdiction)

### Before Public Disclosure

- [ ] Evaluate whether any technical innovation has patentable value
- [ ] Consider filing before public release (public disclosure can destroy novelty)
- [ ] Review: GitHub commits, blog posts, demos, conference talks, sales materials
- [ ] Any public technical documentation should be reviewed for patent exposure

### Patent Filing Considerations

- [ ] Provisional patent application (if innovation is significant)
- [ ] Cost-benefit analysis of filing vs. trade secret protection
- [ ] Jurisdiction selection (CN, US, PCT)
- [ ] Prior art search before filing

## Trade Secret Protection

Content that must NOT be publicly disclosed without authorization:

- [ ] Proprietary algorithms or business logic
- [ ] Customer lists and pricing strategies
- [ ] Internal architecture decisions not needed for API users
- [ ] Security mechanisms and key management
- [ ] Unpublished roadmap details

### Trade Secret Safeguards

- [ ] Access control (repository visibility, branch protection)
- [ ] NDAs for all contributors and contractors
- [ ] Permission logs for sensitive document access
- [ ] Offboarding procedure to revoke access and recover materials
- [ ] Regular audit of who has access to what

## Checklist Before Any Public Release

| Item | Status |
|------|--------|
| Trademark search completed | ☐ |
| Domain/social handles secured | ☐ |
| First-use evidence preserved | ☐ |
| Patentability assessment done | ☐ |
| Trade secrets identified and protected | ☐ |
| Third-party trademark clearance | ☐ |
| Legal review of marketing materials | ☐ |

*This checklist does not constitute legal advice. Consult an IP attorney before major public disclosures.*
